# OpenTrust vs. OpenThread: Differences

OpenTrust is a clean re-implementation of Thread 1.4.1 in Rust, not a port.
OpenThread (`thread-reference-20250612`, vendored in
`tools/openthread-sys/vendor/openthread`) is the reference for behaviour,
constants and test vectors. This file records every place where OpenTrust
deliberately behaves differently, why, and whether it affects interop.

**Interop** column: **none** = invisible on the air / to peers;
**stricter** = OpenTrust rejects some input OpenThread accepts (still
interoperable with spec-conformant peers, including OpenThread);
**API** = only affects the programming interface.

Keep this file up to date with every change that deviates from OpenThread.

## Architecture

| Area | OpenThread | OpenTrust | Reason | Interop |
|------|------------|-----------|--------|---------|
| Language / memory | C++, global instance, intrusive lists, heap optional | Rust, `no_std`, no alloc, no `unsafe` in protocol crates | Memory safety, embedded targets | none |
| Execution model | Single-threaded tasklets, timers, callbacks; platform calls in (`otPlat*`) | I/O-free core state machines (caller passes `now`) + executor-agnostic async facade | Deterministic tests, rs-matter integration | API |
| Time base | `TimerMilli` (ms) and `TimerMicro` (µs) | One `Instant`/`Duration` type, `u64` µs | Single type, CSL needs µs | none |
| Platform radio API | `otPlatRadio*` functions + callbacks | Async `Radio` trait mirrored from esp-rs/openthread; `RadioCaps::soft_mac_needs()` tells the MAC what to do in software; `MacCapabilities::missing_required()` instead of a panicking assert | Drop-in for esp-rs/openthread radio drivers | API |
| Clock / alarm | `otPlatAlarmMilli*` / `otPlatAlarmMicro*` | Own `Clock` / async `Alarm` traits; `embassy-time` adapter belongs in `opentrust-embassy` | Keep platform crate free of embassy-time driver choices | API |
| Entropy | `otPlatEntropyGet` | `rand_core::CryptoRng` (0.10) | Same type as rs-matter / esp-rs openthread | API |
| Logging | `otLog*` | `opentrust_core::{trace,debug,info,warn,error}!` → `defmt` or `log` | Embedded Rust conventions | none |
| DTLS / EC-JPAKE | mbedTLS | Rust EC-JPAKE on RustCrypto `p256` (`opentrust_core::crypto::ecjpake`) + minimal sans-IO DTLS 1.2 (`opentrust-dtls`, ADR 0001); mbedTLS only as test oracle. Details in "DTLS / EC-JPAKE" below | No heap, no C toolchain, no `unsafe` | none (byte-compatible with mbedTLS 3.6; see below) |

## Core (`opentrust-core`)

| Area | OpenThread | OpenTrust | Reason | Interop |
|------|------------|-----------|--------|---------|
| Message buffers | Chained 128-byte buffers, ref-counted, `Message::Type`, datagram tag, timestamps | Fixed contiguous slots with headroom for prepends; no type/tag/timestamp/ref-count yet | Simplicity; add fields when upper layers need them | none |
| Settings keys | `uint16_t` keys | Typed `SettingsKey` enum (+ `Vendor(u16)` escape hatch); same numeric values and byte layouts for `NetworkInfo` / `ParentInfo` | Type safety; blobs stay comparable with OT | API |
| Secret key types | Plain byte arrays, copyable | `NetworkKey`, `Pskc`, `MacKey`, `MleKey`, `Kek` are not `Copy`, zeroize on drop, compare in constant time, redacted in `Debug`/`defmt` | Key hygiene | none |
| MLE/MAC key split (spec §7.1.4) | First 16 bytes = MLE key, last 16 = MAC key | Same as OpenThread; the spec *text* ("MAC key = upper 16 bytes") contradicts its own test vectors, OpenTrust follows the vectors and OT | Interop | none |

## MAC frames (`opentrust-mac::frame`)

| Area | OpenThread | OpenTrust | Reason | Interop |
|------|------------|-----------|--------|---------|
| PSDU / FCS | Frame length includes FCS | All frame APIs work on the PSDU **without** FCS; `Frame::parse_with_fcs` strips it | Radios handle FCS | none |
| Sequence-number suppression / IE-present bits | Honoured regardless of frame version | Honoured only for 2015 (and multipurpose) frames; reserved bits in 2003/2006 | IEEE 802.15.4-2015 | stricter |
| Frame-counter suppression | Not supported | Parsed/built (no counter field when suppressed) | Completeness | none |
| Command ID in 2015 frames | Treated as first payload byte | Same (encrypted when the frame is secured); in 2003/2006 frames it counts as header | Matches OT | none |
| Enh-ACK key identifier | Copies key index from the acked frame | Copies the full key identifier (mode, source, index) | Correct for key ID mode 2 acks | none |
| Typed header IEs in builder | Unlimited | Up to `MAX_HEADER_IES` (6) typed IEs; more via `raw_header_ies` | Fixed-size, no alloc | API |

## MAC security (`opentrust-mac::security`)

| Area | OpenThread | OpenTrust | Reason | Interop |
|------|------------|-----------|--------|---------|
| Key ID mode 2 rx | Key source / index not checked | Requires key source `ffffffff` and key index `ff` | Thread §7.2.1.3 (lookup MUST match mode, source, index); OT sends exactly these | stricter |
| Previous/next key at sequence edges | `seq - 1` / `seq + 1` with wraparound | No "previous" key at sequence 0, no "next" at `u32::MAX` (radio `MacKeys` still carries the wrapped keys, like OT) | Avoid accepting keys of a wrapped sequence | stricter |
| Key sequence decrease | Possible via API | `set_key_sequence` rejects a lower value; only `set_network_key` / `restore` may lower it | Thread §7.1.3 | none |
| Frame counter exhaustion | Wraps | Never uses `0xffffffff`; returns `InvalidState` when exhausted | Never reuse a nonce | none |
| Replay counters | `u32` | Stored as `u64`, so receiving `0xffffffff` does not let a counter of `0` pass afterwards | Replay safety | stricter |
| Minimum key rotation time | 2 h | 1 h | Thread spec minimum | none |
| Key switch guard | Hourly countdown | Deadline-based (`Instant`), same effective behaviour | Sans-IO timers | none |
| Rx security-level policy | Only ENC-MIC-32 | Default only ENC-MIC-32; optional `Authenticated` policy accepts any level with a MIC, never level 4 (ENC without MIC) | Configurable, still safe | none |
| Order of replay check | Before decryption | After decryption (contract returns `RxSecurityInfo`; replay state lives in the neighbor table) | Layering; same outcome, only costs a CCM on replayed frames | none |
| Retransmissions | Re-secure allowed per case | A plain retransmission must resend the already-secured PSDU; calling `secure_tx` again uses a new counter (needed for CSL-IE updates) | Documented contract | none |
| Key ID mode 0 (KEK) | `Mac::ProcessTransmitSecurity` / `ProcessReceiveSecurity` with `KeyManager::GetKek`, `mKekFrameCounter` | `KeyManager::set_kek` and key ID mode 0 in `secure_tx` / `unsecure_rx` (same nonce source, same counter reset on a new KEK); without a KEK, mode 0 is `InvalidState` on transmit and `Security` on receive | Same behaviour; the caller routes mode-0 frames only to the Joiner Entrust handlers | none |

## MAC state machine (`opentrust-mac::mac`)

| Area | OpenThread | OpenTrust | Reason | Interop |
|------|------------|-----------|--------|---------|
| Structure | `Mac` + `SubMac` + callbacks | One sans-IO `Mac` core (pull-style `poll_action` / `on_tx_done` / `on_rx` / `poll_event`) + async `MacDriver`; no internal channel, the facade passes a wake future | Executor-agnostic, deterministic tests | API |
| Radio PSDU / FCS | Radio frame buffers include FCS | Radio-side PSDUs include FCS; the MAC computes it on tx and strips it on rx; upper layers never see it | Matches the `Radio` contract | none |
| Source-match table at start | Disabled → frame pending set for every poll | Enabled and empty → frame pending only for children with queued frames | Avoid needless wake-ups of sleepy children | none |
| Promiscuous mode | Filtered delivery with flags | Delivers raw, unfiltered frames | Sniffer use | API |
| Frames to short address `0xfffe` | Accepted in some paths | Never accepted | `0xfffe` means "no short address" | stricter |
| Unsecured frames from unknown short source | Dropped in MAC (neighbor lookup) | Delivered; the neighbor table (MLE) decides | Neighbor table lives in MLE | none (policy moves up) |
| Software ACK timing | n/a (radio does ACKs) | Software ACKs only meet the 802.15.4 turnaround on simulated media | Bare PHYs need HW ACK in production | none in sim |
| Energy scan without radio support | Software RSSI sampling via `otPlatRadioGetRssi` | `Error::NotImplemented` (the `Radio` trait has no RSSI read) | Trait mirrors esp-rs/openthread | API |
| Not yet implemented | — | Broadcast retransmission, stay-awake between fragments, MAC allow/deny filter, wake-up frame tx/rx flow, hardware-ACK radios reporting enh-ACK link metrics | Later waves / phases | — |
| Queue capacities | Compile-time config macros | Const generics of `Mac` / `MacDriver` with defaults: direct queue 4, indirect 8, events 8, poll requests 4, neighbor map 32, CSL children 8. `Mac::new` / `MacDriver::init` use the defaults; `Mac::with_capacities` + `MacDriver::new` take others (a `Mac::new` call cannot infer non-default const params) | no global config, several MACs per binary | none |
| Radio key / frame-counter push | `SubMac::SetMacKey` / `SetFrameCounter` called by `KeyManager` on every change | The MAC compares `FrameSecurity::radio_keys()` with what it pushed last at every `poll_action`, so *any* change through `Mac::security_mut()` (key switch, network key change) reaches the radio as `RadioAction::SetMacKeys` + `SetMacFrameCounter(.., if_larger = false)`; later counter growth (software-secured frames) is pushed with `if_larger = true`; radios with `TRANSMIT_SEC` or `RECEIVE_TIMING` only | No change notification plumbing between `KeyManager` and `Mac`; sans-IO | none |
| Frame counter feedback | `SubMac::SignalFrameCounterUsed` from the radio callbacks | `Mac::on_tx_frame_updated(psdu, info)` (driver calls it after a `TRANSMIT_SEC` transmit, also stores the radio-updated frame for retransmission) and `PsduRxInfo::ack_security` in `on_rx` feed `FrameSecurity::frame_counter_used` / `ack_frame_counter_used` | Explicit data flow instead of callbacks | none |
| Software enh-ACK security | Done by the radio (`otMacFrameProcessTransmitSecurity`) | `FrameSecurity::secure_enh_ack` (KeyManager: key index copied from the acked frame, prev/cur/next key, next frame counter); falls back to `secure_tx` for other key modes | Same result for bare PHYs / simulation | none |
| CSL needs a radio clock | `otPlatRadioGetNow` always available | `Mac::set_csl` / `csl_add_child` return `Error::NotImplemented` when `RadioCaps::clock` is `None` | The trait has no mandatory clock | API |
| CSL phase reference | `ComputeCslPhase(SFD time)`, parent: `last_rx_timestamp + phase * 160` | Same convention as OpenThread (SFD/timestamp based), not the spec text's "first symbol of the MAC header" (a 32 us PHR offset that OT absorbs in `CSL_TRANSMIT_TIME_AHEAD`) | Interop with OT | none |
| CSL IE in outgoing frames | Upper layer (`MeshForwarder`) appends the IE, radio fills phase | Same: the MAC never inserts a CSL IE, it only updates the phase/period of a frame that already carries one (placeholder from `FrameBuilder::header_ie(CslIe)`); data polls built by the MAC do not carry one yet | Frames are built by the upper layer | none |
| CSL IE phase without `TRANSMIT_SEC` | Radio platform must support it (capability required for CSL) | Software fallback: phase from the radio clock at the start of the attempt plus CCA + SHR (288 us); the frame is re-secured with a new frame counter on every attempt (`TxOp::csl_plain`) | Bare PHYs / simulation | accuracy (parent's window absorbs it) |
| CSL receiver without `RECEIVE_TIMING` | `HandleCslReceiveOrSleep` (timer twice per period) | Same algorithm in the MAC (`desired_mode` is Receive on the CSL channel while sampling) | — | none |
| CSL receive window handover | `otPlatRadioReceiveAt` is called even while in other sub-MAC states | `RadioAction::ReceiveAt` only once the radio is asleep and the MAC wants to sleep; dropped for rx-on-when-idle devices and when stale | A window must not cancel (or be cancelled by) a pending `Sleep` / transmit | none |
| CSL transmitter child table | `ChildTable` entries (`IsCslSynchronized`, ...) | `Mac::csl_add_child` registers a child explicitly; its CSL IEs (rx frames and ACKs, 2015 + secured, period >= 10) synchronize it; the CSL synchronized timeout, CSL channel TLV and accuracy TLV are set by MLE (`csl_child_desync`, `csl_set_child_channel`, `set_csl_parent_accuracy`) | Child table lives in MLE | none |
| CSL tx scheduling | `RescheduleCslTx` picks the earliest child, `Mac::RequestCslFrameTransmission(ms)` | Same selection with a microsecond timer (`TimerId::CslTx`) and a dedicated operation `TransmitDataCsl`; request-ahead 2000 us + radio bus time, guard 1500 us, as OT; failed CSL tx keeps the frame with its counter/sequence, 4 NO_ACKs -> `Event::CslChildOutOfSync` | — | none |
| Timed transmit without `TRANSMIT_TIMING` | `SubMac` timer before `BeginTransmit` | Same (`tx_at - (CCA 128 + 40 + SHR 160)`), the MAC waits using the radio clock; with `TRANSMIT_TIMING` the SFD time goes to the radio in `PsduTxInfo::tx_at_us` | — | none |
| Enh-ACK probing (subject) | Radio platform keeps the table (`otPlatRadioConfigureEnhAckProbing`) | The MAC keeps it (`configure_enh_ack_probing`, 8 entries) and adds the IE to *its own software* enh-ACKs; a radio that acknowledges in hardware cannot (no trait method) | The `Radio` trait mirrors esp-rs/openthread, which has none | feature gap |
| Enh-ACK probing data | LQI, margin (truncated `*255/130`), RSSI; three metrics accepted but only two bytes sent | Same order, fixed regardless of the request order; at most two metrics are accepted (`InvalidArgs`); scaling rounds to nearest like OT's initiator-side `ScaleLinkMarginToRawValue`; raw 0 RSSI saturates at -128 dBm (OT's `int8_t` wraps); no IE if a requested metric is unknown | Spec limits to two metrics; avoid OT's inconsistencies | none |
| Enh-ACK probing (initiator) | `Mac::ProcessEnhAckProbing` -> `Initiator::ProcessEnhAckIeData` with the neighbor's configured metrics | `track_enh_ack_probing` keeps the metrics per neighbor; the IE of ACKs to our frames is reported as `Event::EnhAckLinkMetrics` | MLE (Phase 6) calls it | none |

Matches OpenThread (listed because a draft said otherwise): `macMaxFrameRetries` = 15 for direct frames (Thread §3.2); indirect frames use 0 retries per poll and up to 4 polls.

## 6LoWPAN (`opentrust-lowpan`)

| Area | OpenThread | OpenTrust | Reason | Interop |
|------|------------|-----------|--------|---------|
| API shape | `Lowpan::Compress/Decompress` work on `Message` + `FrameBuilder`/`FrameData` and read Network Data directly | Functions on byte slices (`compress`, `decompress`, `decompress_datagram`); contexts come from a `ContextProvider` trait (`ContextTable` is a ready implementation) | Sans-IO, no global Network Data; `opentrust_mesh::netdata::consumers::NetDataContexts` implements the trait | API |
| IPv6 types | Full `Ip6::Header`/`Udp::Header` | Minimal `Ipv6Header`/`UdpHeader` in `opentrust_lowpan::ip6`, re-exported by `opentrust_net::header` (which adds setters and the extension headers); the codecs take/produce raw datagram bytes | Avoid a dependency cycle between lowpan and net | API |
| Context prefix length | Up to 128 bits | Same (bits beyond /64 are applied to the IID); stateful multicast uses the first 64 prefix bits like OT | — | none |
| Link-local detection when compressing | `IsLinkLocalUnicast` (`fe80::/10`); the decompressor restores `fe80::/64`, so `fe80:0:0:1::x` would be corrupted | Only `fe80::/64` is treated as link-local, other `fe80::/10` addresses fall through to context/inline | Round-trip correctness | none |
| Stateful multicast without context 0 | Compares against a cleared context (prefix length 0, all-zero prefix), which can wrongly match | Requires a real context 0 | Round-trip correctness | none |
| Multicast with an all-zero group (`ffXX::`) | Emits no address bytes | Sent inline (128 bit) | Round-trip correctness | none |
| SAM/DAM = 11 without MAC address | Source: IID left zero; destination: parse error | Parse error for both | Do not invent addresses | stricter |
| Context applied to link-local mode 3 | `ComputeIid` applies context 0's bits beyond /64 even when SAC = 0 | Context only used when SAC/DAC = 1 | RFC 6282 | none |
| Traffic class/IPv6 version | Compress reads the header without checking the version | `Ipv6Header::parse` requires version 6 (`Error::Parse`) | Defensive parsing | stricter |
| NHC chaining at the header-depth limit | When the compressed-header budget forces fewer compressed headers, the Hop-by-Hop NHC may still announce a compressed next header | NH bit only set if the next header will really be compressed | Round-trip correctness | none |
| ECN accessors | `DecompressEcn`/`MarkCompressedEcn` read the byte at offset 2 even when a context-ID byte is present | `iphc_ecn`/`iphc_mark_ecn` skip the context-ID byte | Correctness | none |
| Extension headers | Compresses Hop-by-Hop only; decompresses Hop-by-Hop/Routing/Fragment/Destination/IP-in-IP NHC | Same | — | none |
| UDP checksum | NHC with elided checksum rejected | Same (Thread requires inline checksum) | — | none |
| Mesh header | Short originator/destination only; hops left 0-255 (deep hops) | Same; `MESH_HEADER_HOPS_LEFT` = 19 (`kMaxRouteCost` 16 + 3) | — | none |
| Fragment header | Offset in 8-byte units; `FRAGN` with offset 0 accepted and treated as first fragment | Same | — | none |
| Reassembly storage | `Message`s from the pool in a reassembly list | Fixed const-generic slots (`Reassembler<SLOTS, MAX_DATAGRAM>`, default 1280 B each) holding the uncompressed datagram; completion returns `&[u8]` | No alloc; Phase 4 copies into a `Message` if needed | API |
| Reassembly key | Datagram size + tag (+ offset, link security); source address not compared | (originator address, size, tag) plus offset and link security | Avoid mixing datagrams of different senders with equal tags | stricter |
| Duplicate FRAG1 | A second reassembly is started | Dropped while a reassembly with the same key is pending | Retransmitted FRAG1 must not reset progress | none |
| Out-of-order / duplicate FRAGN | Dropped, pending reassembly kept | Same (`Error::Drop`) | — | none |
| Reassembly timeout | 2 s granularity via the 1 s time ticker, refreshed by each fragment | Exact deadline (`next_deadline`/`expire`, 2 s), refreshed by each accepted fragment | Sans-IO timers | none |
| Sleepy-device reassembly | Clears the list on a new secure first/mismatching next fragment | Not built in; `Reassembler::clear()` for the role layer | Role is MLE's concern | none |
| Fragmenter | Per-message state in `Message` (offset, tag), 0 = unset tag | `Fragmenter` iterator with caller-supplied tag; `TagCounter` never yields 0 | Sans-IO | API |
| Fragment size limit | `uint16_t` size masked to 11 bits | Datagrams above 2047 bytes are rejected when fragmenting (`InvalidArgs`) | Avoid silently wrong size | stricter |
| Mesh forwarding | `HandleMesh` mixes parsing, routing, queueing | `handle_mesh` only decides (deliver/forward/drop) via `LocalRlocs`/`NextHops`; a 2-hop loop is reported as `DropReason::RoutingLoop` and the caller invalidates the route; no route is detected immediately (OT drops at send time) | Routing table is Phase 7 | API |

## Network layer (IPv6) (`opentrust-net`)

| Area | OpenThread | OpenTrust | Reason | Interop |
|------|------------|-----------|--------|---------|
| API shape | `Ip6`, `Udp`, `Icmp`, `Mpl`, `Netif` operate on `Message`s from the global pool and read the instance (MLE, Network Data, child table) directly | Byte-slice datagrams, caller-provided `Scratch` space, time/RNG in `Ctx`, and an `Ip6Env` trait for role, Network Data route lookup, on-mesh test and sleepy children; `Netif`/`Mpl`/`UdpSockets`/`AddressResolver` are plain const-generic structs | Sans-IO, no alloc, no globals | API |
| Message pool | Datagrams and MPL buffered copies live in the shared message pool | MPL buffered messages are stored inline (`BUFS` x 1280 B, default 4); no pool involvement in `Ip6`/`UdpSockets` | Simple ownership without lifetimes in the public types; sizes are explicit | API |
| Extension-header validation | Only the Hop-by-Hop header is parsed for datagrams that are merely forwarded; other headers only when receiving | The whole chain is always validated (`parse_datagram`); malformed or unsupported chains are dropped even if they would only be forwarded | One parser, defensive | stricter |
| Routing header | Dropped (when processed) | Parsed and skipped by the parser; dropped by the receive path when the datagram is for us, ignored when only forwarding | Parser reusable for other callers | none |
| Fragment header | Atomic fragments walked; others dropped unless `IP6_FRAGMENTATION_ENABLE` | Same as the default build (no IPv6 reassembly; non-atomic fragments dropped) | Not needed for Thread | none |
| `RemoveMplOption` | Strips the MPL option before passing datagrams to the host | Not implemented (no host interface yet) | Phase 9 border routing | API |
| Host handling | `PassToHost` has extra policy (multicast loop, border-router counters, backbone) | `RxOutcome::forward_host` only reflects `DetermineAction` | No host interface yet | API |
| MPL timing and Trickle | Proactive forwarding with a custom random schedule (`GenerateNextTransmissionTime`, 64 ms window, router: 2 total transmissions, child: 0); **no RFC 6206 Trickle** | Same algorithm and constants, as deadlines on `Instant`; `opentrust_core::trickle` is deliberately not used because OpenThread does not use Trickle for MPL | Interop with OpenThread's observable retransmissions | none |
| MPL randomness | `Random::NonCrypto::GetUint8InRange` | `Rng::next_u32() % interval` with the caller's RNG (bias < 2^-24) | Deterministic tests | none |
| MPL seed lifetime tick | `TimeTicker` (shared 1 s tick) | Own 1 s deadline chain started at the first seed insertion | Sans-IO | none |
| MPL sleepy-child copy | `PrepareMulticastToLargerThanRealmLocal` clones the datagram for sleepy children that subscribed | Not done in `Ip6::send`; `DetermineAction` honours `has_sleepy_child_with_address` for received datagrams only | Child table is Phase 7 | API |
| Datagram size | `kMaxDatagramLength` 1280 and optional IP fragmentation | 1280 hard limit (`Error::NoBufs`) | Same default | none |
| UDP checksum | `VerifyMessageChecksum` | Verified in `Ip6::handle` (UDP: zero checksum and length mismatches dropped as OT does); `UdpSockets` re-checks the length | Defensive | none |
| UDP delivery rules | Socket list with head insertion; first match wins; multicast matches any socket on the port | Same matching rules; among overlapping matches the most recently opened socket wins (same effect as head insertion) | — | none |
| UDP bind conflicts | Platform bind decides; the internal list accepts duplicates | Explicit `Error::Already` for overlapping address/port bindings; internal receivers' ports cannot be bound | Predictable socket API for `edge-nal` | stricter |
| Ephemeral port | `GetEphemeralPort` skips TMF and SRP-server ports | Same, and also skips ports already bound | Avoid collisions without a platform bind | none |
| UDP receive queue | Callback per datagram | Bounded per-socket queue (`Q` packets of `BUF` bytes); overflow counted and dropped; longer payloads truncated with a flag | Async facade pulls data | API |
| ICMPv6 error generation | `Icmp::SendError` quotes the IPv6 header only, no limiter; errors only from the mesh forwarder/reassembly | `Ip6::build_error` quotes the IPv6 header only (like OT) and adds RFC 4443 section 2.4 suppression rules (no errors for errors, unspecified/multicast sources, multicast destinations except Packet Too Big/Param Problem code 2) and a token-bucket rate limiter (burst 10, one per 100 ms) | RFC 4443 compliance; OT has no limiter | none |
| Hop-limit exhaustion | Silent drop (no Time Exceeded) | Same | Matches OT | none |
| Echo responder | Replies via `SendDatagram` | Reply datagram built into `Scratch`; echo to our own address is not looped back through the reply path | Edge case | none |
| Source selection | `Ip6::SelectSourceAddress` | Same rules, including the RLOC rule; ALOCs are skipped before the "same address" rule as in OT | — | none |
| Address scope | `Address::GetScope`; mesh-local addresses get a realm-local scope override | Same | — | none |
| Multicast API errors | `kErrorRejected` for fixed/non-external groups | `Error::InvalidArgs` (no `Rejected` in the shared error type) | Error set | API |
| All-Thread-nodes groups | Subscribed by MLE when the mesh-local prefix changes | `Netif::set_mesh_local_prefix` (re)subscribes `ff32:40:<mlp>::1` and `ff33:40:<mlp>::1` itself | Keeps prefix-derived state consistent in one place | none |
| SLAAC IID | SHA-256(prefix, "wpan", DAD counter, 32-byte secret); Network_ID not used; secret persisted in settings | Same, with an optional RFC 7217 Network_ID (`None` = OT-compatible); secret is a caller argument | Persistence is the caller's | none |
| SLAAC manager | Reads Network Data, filter callback, notifier events | Takes the on-mesh prefix list as input (`OnMeshPrefix`), filter as `fn` pointer, 1 s deadlines instead of the time ticker; `netdata::consumers::slaac_prefixes` builds the list | Sans-IO | API |
| SLAAC context ID tracking | Updates the 6LoWPAN context ID per address and notifies MLE | Not tracked | Phase 7 | API |
| Address resolver API | Calls `MeshForwarder::HandleResolved`, sends TMF directly | Emits `ResolverEvent`s (send query/error, resolved/failed) to a caller sink; replies to `/a/aq` are decided by `address_query_response` | CoAP/TMF are Phase 5/7 | API |
| Address resolver lists | Four intrusive linked lists | One entry array with a state and an insertion counter (same eviction order and capacities) | No alloc, no pointers | none |
| Address resolver extras | `ResolveUsingNetDataServices`, Backbone Router queries, DUA, `/a/ae` child handling | Not implemented | Phases 7/9 | API |
| DHCPv6 | Optional client/server | Not implemented | Legacy; no use case yet | none |

## CoAP / TMF (`opentrust-coap`, TLVs in `opentrust-core::tlv`)

| Area | OpenThread | OpenTrust | Reason | Interop |
|------|------------|-----------|--------|---------|
| Generic TLVs | `Tlv` / `ExtendedTlv` structs over `Message` | `opentrust_core::tlv`: slice-based `Tlv::parse`, `TlvIter`, `find`, typed readers, `write*`/`write_with` (extended form iff value > 254 bytes); lives in core so MLE/MeshCoP reuse it | No message-chain abstraction; no dependency on CoAP | none |
| Message API | `Message` mutated in place, `Finish()` writes the header | Zero-copy `Message::parse` + `MessageBuilder` over a caller buffer; options must be added in order (`InvalidArgs` otherwise, as OT) | no alloc / no unsafe | API |
| Parse strictness | `ParseHeader` does not check the version or the empty-message rules | Version != 1 is ignored silently (RFC 7252 3); empty message (0.00) with token/options/payload is a format error | RFC 7252 3 / 4.1 | stricter |
| Format-error reply | RST for CON, unicast only | Same (needs a readable header with version 1) | | none |
| Sans-IO endpoint | `CoapBase` with callbacks, timers, message queues | `Endpoint<REQ, RES, CACHE, MSG>`: caller feeds datagrams and time, output via `Transport`; outcomes are `Rx::{Request,Response,Failed}` / `Event::Timeout` carrying a caller `u32` instead of handler pointers | Executor-free, fixed capacity | API |
| Retransmission | `TxParameters` (2000 ms, 3/2, 4), ACK stops retransmission but the request still times out after the remaining back-off | Same numbers and behaviour, deterministic with a caller RNG; `exchange_lifetime` 247 s, `max_transmit_wait` 93 s | | none |
| Duplicate detection | Response cache keyed by (message id, peer), 10 entries, earliest-expiry eviction | Same (capacity `CACHE`); like OT only requests that already have a cached piggybacked response are recognised as duplicates | | none |
| Multicast response jitter | none in the CoAP layer (individual handlers delay) | none in the endpoint; handlers delay | same as OT | none |

## Instance (`opentrust-instance`, [ADR 0003](docs/decisions/0003-instance.md)) and `opentrust-sim`

- **No `otInstance` singleton, no callbacks.** One owned struct; the radio is not a type parameter: the host calls `handle_radio_rx` / `handle_radio_tx_done` and executes `RadioAction`s from `poll_radio_action` (the MAC's pull model). Application notifications are a bounded `Event` queue (`poll_event`, latest wins when full) instead of `otSetStateChangedCallback` flag masks (`OT_CHANGED_*`) and per-feature callbacks; internal consumers of changes (SLAAC, ALOCs, publisher, notifier, address cache, MAC neighbor / source match tables) are driven from one place (`Instance::poll`), not from the Notifier.
- **Two random sources.** The CSPRNG passed to `Instance::new` serves MLE challenges, the ML-EID IID and the SLAAC secret; CoAP tokens, MPL / TMF jitter and the MAC backoff use seeded xorshift generators (the `meshcop` simulators do the same). OpenThread draws all of them from `otPlatEntropy`.
- **Frames wait in an instance queue** (32 frames) for room in the MAC's 4-frame transmit queue; OpenThread's `MeshForwarder` keeps whole messages in its send queue and prepares one frame at a time. A datagram whose fragments do not all fit is dropped (`NoBufs`).
- **Data poll period.** `set_poll_period` takes the shorter of the application's period and the MLE default (OT: external period replaces the default while it is shorter, same effect); MLE sets the default to child timeout minus 4 s (OT `GetDefaultPollPeriod`).
- **Unsecure-port filter** (OT `Ip6::Filter`) accepts unsecured UDP only for the MLE port and the ports added with `add_unsecure_port`; ICMPv6 and TCP without link security are always dropped (OT additionally lets the Joiner Router open its port automatically, not wired yet).
- **Children that moved** (`Mle::remove_child_that_moved`) are detected only for mesh header frames that end at this router; OT also examines frames it forwards (the forwarder does not expose the inner IPv6 source).
- **Link-layer replay protection** (`Mle::check_link_frame`) runs in the instance before the forwarder; OT does it in `Mac::ProcessReceiveSecurity`. Frames from unknown neighbors pass (OT drops secured frames from unknown short addresses; the MAC here drops them already when no short -> extended mapping exists, so only extended-address frames from unknown sources pass).
- **Formation.** `thread_start` follows OT (attach, become leader if no partition answers); `become_leader` is `otThreadBecomeLeader`. `create_dataset` is `otDatasetCreateNewNetwork` with a fixed network name, channel mask of page 0 and default Security Policy; the Active Timestamp starts at 1 second.
- **MTD-only builds.** The forwarder is `ftd`-only, so the data path of an end-device-only build is not implemented yet; the crate builds, `ftd` is a forwarded feature of the lower crates.
- **Simulator radio.** `opentrust-sim` models a MAC-offload radio (`TX_ACK`, `RX_ACK`, `SRC_MATCH`, CSMA backoff, retries, ACK timeout, energy scan; address filtering stays in the MAC) with air time (32 us / byte + SHR / PHR), 192 us turnaround, 16 tries per frame and independent per-direction loss. It does not model collisions, CCA by other nodes (only forced jamming), timed receive windows / CSL, or capture effects. It is not the OpenThread simulation platform protocol (Phase 11).


### End-device-only builds (`default-features = false`)

- The workspace dependencies on `opentrust-mle`, `opentrust-mesh` and `opentrust-meshcop` no longer enable their default features, so an `opentrust-instance` build without `ftd` really has no router, leader, Router ID, indirect queue user or commissioner code (before, feature unification pulled `ftd` in everywhere).
- `opentrust-mesh::forwarder` / `indirect` are compiled without `ftd` (OT `mesh_forwarder.cpp` + `mesh_forwarder_mtd.cpp`); the MLE offers a parent-only `next_hop_and_path_cost` in that build. Mesh header frames are dropped on receive without `ftd` (OT `HandleReceivedFrame`: `HandleMesh` is FTD only). The `MeshForwarder` struct still contains the (empty) indirect queue instead of being a separate type; OT has no queue object in MTD builds. An end device sends everything except link-local to its parent, as in OT `UpdateIp6RouteMtd`.
- The `Instance` of such a build serves only Address Notify / Address Error / Anycast Locate / dataset Get on TMF and has no `become_leader`.
- Deviation in test coverage: the sim harness cannot mix `ftd` and non-`ftd` instances in one binary (feature unification), so the end-device build is tested at the instance level (start, Parent Request on the dataset channel); full attach of mode-MTD nodes is covered by the existing sim tests.

### SRP and DNS client in the `Instance` (`opentrust-instance::dns_srp`)

- Always compiled (no `srp` feature): Matter needs it and the conventions of the other layers make `opentrust-dns` an unconditional dependency of the instance. The price is the `EcdsaP256` bound on the crypto backend and a `CryptoRng` bound on the RNG of `Instance` (the SRP key is generated from it); `SoftCrypto` provides both.
- UDP goes through two internal instance sockets (ephemeral ports, opened on first use) instead of one socket per client; they take two of the `UDP_SOCKETS` slots (now 5). Datagrams queued on them never reach the application.
- DNS results are owned (`DnsOutcome`; a browse result keeps at most 4 instances with their additional-section data) and fetched with `dns_take_result` after `Event::DnsResult`; OT calls a callback with a borrowed response. Two results can be pending; the oldest is dropped.
- The SRP client key is stored as the raw 32-byte scalar under `SrpEcdsaKey` (OT: DER), the server as 16-byte address + 2-byte port under `SrpClientInfo` (as OT).
- `Event::SrpClient(SrpEvent)` replaces the OT `otSrpClientCallback`, the auto-start server is set as the DNS default server.
- Network Data is fed to `SrpClient::handle_network_data` whenever the Network Data bytes or the mesh-local prefix change (hash comparison), the interface addresses to `on_addresses_changed` when the set of preferred non-link-local non-mesh-local addresses changes.
- `Instance::publish_dns_srp_service` / `unpublish_dns_srp_service` expose the Network Data Publisher's DNS/SRP entry (`otNetDataPublishDnsSrpService*`).

### Sleepy children attaching and polling (Instance glue)

- The parent sends link-local unicast messages to a sleepy child indirectly only after the child is `Child::confirmed` (it has sent a Child Update Request, or was restored). OT sends the Child ID Response indirectly to the child's extended address; here the response goes out directly while the child still listens, because the indirect path addresses frames by RLOC16, which the child does not know yet.
- Attach mode of the data poll sender (`Mac::set_poll_attach_mode`, 100 ms) and fast polls after a Data Request (`MleEnv::send_fast_polls`) are implemented; attach-mode polling is not started right after the Child ID Request as in OT (see above).

### DUA, MLR and Backbone Router client in the `Instance` (`opentrust-instance::bbr`)

- The DAD counter is persisted under `DadInfo` as one byte (OT `DadInfo`), written whenever the manager changes it, read on `thread_start`.
- Domain Unicast Addresses and external multicast groups are registered through the address registration of the Child Update Request (as OT) and, for the device itself and its children, with `/n/dr` and `/n/mr` to the Primary Backbone Router from the Network Data. There is no Backbone Router server role; `Instance::set_tmf_extension(uris, fn)` lets a layer on top serve extra TMF URIs (a plain function pointer, answer payload at most 64 bytes) and is how the simulator test plays the Backbone Router.
- `Instance::add_service` / `remove_service` expose the local Network Data services.

### CSL and link metrics glue in the `Instance`

- `MleEnv::set_csl` calls `Mac::set_csl`; without a radio clock (`RadioCaps::clock`) the MAC refuses (`NotImplemented`) and the device keeps polling, whereas OT asserts the capability. The CSL clock accuracy reported to children comes from `RadioCaps::csl_accuracy_ppm` / `csl_uncertainty` and only if the radio has a clock.
- Frames of a CSL synchronized sleepy child get a CSL IE (version 2015 frame, phase filled in by the MAC) when the destination is not broadcast; OT adds it to frames to the parent only, which is the same set for an end device.
- A received frame with a CSL IE from a child calls `Mle::child_csl_synchronized` and flushes the frames queued for CSL children; `Event::CslChildOutOfSync` calls `child_csl_desynchronized`.
- Link metrics: `aggregate_link_metrics` is fed with received data frames only (LQI and RSSI of the frame); data requests and ACKs are not aggregated because the MAC does not report their LQI. The MAC decodes the enhanced ACK probing IE itself, so `Mle::process_enh_ack_ie_data` (raw IE bytes) is not used: the decoded values are reported as `Event::EnhAckLinkMetrics`. `MleEnv::configure_enh_ack_probing` maps to `Mac::configure_enh_ack_probing`; the initiator side (`track_enh_ack_probing`) is not called yet.
- The simulated radio has no clock or receive timing, so CSL is tested at unit level (`csl_parameters_reach_the_mac`), not end to end.

### Key rotation, Discovery TX options and Network Diagnostics in the `Instance`

- Key rotation, adoption of a newer sequence from a neighbor and a dataset change all raise `Event::KeySequenceChanged`; the MLE persists the network info on its own poll (`KeyManager::needs_store`), as OT stores it on `kEventThreadKeySeqCounterChanged`.
- `TxOptions::channel` / `pan_id` of Discovery and Announce messages are honoured: the MAC gained `Mac::transmit_on` (channel per direct frame) and the frame builder uses the PAN ID. The override is carried through the instance as `MacTx::{channel, pan_id}` set while one outgoing datagram is sent, not as a per-message property as in OT.
- Network Diagnostics server (`/d/dg`, `/d/dq`, `/d/dr`; `/d/da` is received): TLVs Ext Address, Address16, Mode, Timeout (sleepy), Connectivity, Route64 (routers), Leader Data, Network Data, IPv6 Address List, MAC Counters, Child Table, Channel Pages, Max Child Timeout, EUI-64 and Version. Not supported: battery, supply voltage, vendor strings, stack version, MLE counters, Child / Child IPv6 / Router Neighbor / Enhanced Route, non-preferred channels. A response is limited to 256 bytes (the TMF message size): TLVs that do not fit are left out, a Diagnostic Query is answered with one `/d/da` message instead of several. The MAC counters TLV maps `rx_data` to the unicast counter (the MAC has no unicast / broadcast split) and does not count discarded duplicates. `/d/dr` resets the MAC counters only.
- Client side: `Instance::diag_get` / `diag_query` send the request, answers are queued (2 entries) and signalled with `Event::DiagAnswer` / `diag_take_answer` (raw TLVs). Getters: `mac_counters`, `neighbor_table`, `child_table`, `route_table`.
- The SLAAC IID secret is stored under `SlaacIidSecretKey` as 32 raw bytes, as OT does (generated on first start).

### Commissioning in the `Instance` (`opentrust-instance::{commissioning, cm_io, cm_glue, cm_comm, cm_api}`)

- **Crypto parameter**: the instance's `C` is bound by `InstanceCrypto` (a `CryptoBackend` with a cloneable SHA-256, ECDSA P-256 and an associated EC-JPAKE curve type, implemented for `SoftCrypto` with `SoftP256`) instead of a fourth type parameter. OT has a single mbedTLS backend.
- **Link security classes**: `opentrust_core::types::LinkSecurity` (none, network key / mode 1, KEK / mode 0, mode 2) replaces the link security flag of `TxFrame` and keys 6LoWPAN reassembly, so fragments of differently protected frames never form one datagram (OT keys reassembly by the link security flag only).
- **Key ID mode 0 acceptance is narrower than OT**: OT treats a received mode 0 frame as link-secured (`ThreadLinkInfo::mLinkSecurity`) and passes it to every layer while a KEK is installed, with no frame counter check. OpenTrust accepts mode 0 frames only (a) from the one peer of a running KEK exchange (the Joiner Router of our Joiner in the Entrust / Joined state, or the Joiner whose Joiner Entrust is in flight), (b) addressed to our extended address, (c) with a frame counter above the last one accepted under the current KEK (reset when a KEK is installed or cleared), and the reassembled datagram must be UDP from the peer's link-local address (whose IID is the authenticated MAC source) to our link-local address and the TMF port with a valid checksum; it is handed only to `Joiner::handle_kek_datagram` / `JoinerRouter::handle_kek_datagram`, never to IPv6, TMF or forwarding. Everything else is dropped and counted (`Instance::kek_drops`).
- **Key ID mode 2**: frames secured with the well-known mode 2 key are treated as unsecured above the MAC (OT likewise); MLE Announce is now sent with key ID mode 2 (OT `kKeyIdMode2`), it was sent with mode 1 before.
- **Joiner UDP port**: unsecured datagrams to the Joiner UDP port are accepted only between link-local unicast addresses (OT accepts every link-local destination while the role is disabled and the unsecure ports otherwise). The Joiner additionally accepts only its Joiner Router, the Joiner Router only link-local sources (both as in the meshcop modules).
- **Joiner success**: after the Joiner Entrust the instance saves the network key, channel and PAN ID as the Active Dataset and starts Thread itself (`Event::JoinerResult(Ok)`); OT leaves `otThreadSetEnabled` to the application. The rest of the dataset arrives from the parent during attach.
- **Discovery Response PAN**: a frame to another PAN (Discovery Response to a scanner on PAN 0xffff) carries our PAN ID as source PAN ID (OT `SetSource` / `SetDestination`); the scanner takes the PAN of the network from it. The discovery scan tunes the MAC to the scanned channel (OT `DiscoverScanner`).
- **Fragment size**: direct frames are fragmented to the payload their addresses and key ID mode leave (extended addresses with security leave 94 / 95 bytes); OT computes the frame header length per frame as well.
- **Border Agent transport**: the instance has no infrastructure interface; the host passes the external Commissioner's datagrams to `border_agent_receive` and sends those of `border_agent_take_datagram` (OT binds a socket on the backbone netif). DNS-SD advertisement remains the host's job.
- **TMF message size**: FTD builds use 1024-byte TMF messages (Relay Receive / Transmit carry whole DTLS records); MTD builds keep 320.

### Async facade (`opentrust-embassy`)

- **Clock in the resources**: `Resources::new(instance, clock)` stores the `Clock` because every synchronous `Instance` call needs `now` (OpenThread reads its platform clock; esp-rs `openthread` reads `embassy-time`). `OpenTrust::run(radio, alarm)` takes only the radio and the alarm. The alarm must share the time base of the clock.
- **`run` is generic over the raw mutex**, not tied to one executor. Calling a handle method from inside a `with` closure panics (the instance is a `RefCell`).
- **`wait_changed` supports any number of waiters** (esp-rs `openthread` supports one): a generation counter plus `MultiWakerRegistration`. It fires on every `Event` except UDP readiness, not on OpenThread's changed-flag granularity; `wait_changed_after(generation)` avoids a lost wake-up between a state check and the wait.
- **`next_event` is a bounded queue (16)**: when the application falls behind, the oldest event is dropped, like the instance's own queue. UDP readiness is not an event of this stream; each `UdpSocket` has its own waker, woken whenever the socket holds data after a driver step (so a dropped instance event cannot lose a wake-up).
- **Cancellation**: dropping `run` during a transmission or energy scan marks the node; the next `run` reports it to the MAC as aborted (`Instance::abort_radio_in_flight`, a forward of `Mac::abort_in_flight`). Radio configuration commands (channel, filters, keys) cut off by a drop are not repeated; OT has no equivalent because its radio calls are synchronous.
- **`UdpSocket::connect` is a local filter**, not a kernel association: `recv` drops datagrams from other peers, `send_connected` sends to the peer. `send` waits and retries on `NoBufs` instead of failing.
- **edge-nal** (feature `edge-nal`): `UdpStack` / `UdpSocket` implement the `edge-nal` 0.7 UDP traits like `edge-nal-openthread`. `UdpSend::send` has no source address, so datagrams use the socket's address or source selection (a reply is not forced to the address a request was sent to; use the inherent `UdpSocket::send` with `src` for that). IPv4 and `MulticastV4` return `EdgeError::Unsupported`. The feature raises the MSRV to 1.88 (edge-nal's requirement). Multicast join / leave map to `Instance::subscribe_multicast` / `unsubscribe_multicast` (the latter is new); `interface` is ignored (one interface).
- **Request wrappers**: `ping`, `joiner_start`, `srp_wait_*` and `dns_*` await *their* result (matched by echo id / sequence, query id, service state, joiner result) instead of OpenThread's callbacks. The ping timeout is a parameter (OT has none; the application times out itself) and is driven by the `run` future through a request deadline. The wrappers remove their result from the instance queues, so `take_ping_reply` / `dns_take_result` through `with` must not be used for a request a wrapper is waiting for. Dropping a joiner / DNS future stops joining / cancels the query.

### Scans in the `Instance`

- `discover_start` / `active_scan_start` / `energy_scan_start` report through `Event::{DiscoverResult, DiscoverDone, ActiveScanResult, ActiveScanDone, EnergyScanResult, EnergyScanDone}` instead of OT's callbacks. The discovery scan reports one result per responder and channel (OT reports every Discovery Response; a radio that retries an unacknowledged response would repeat it).
- The discovery scan switches the MAC channel to the scanned channel and restores it at the end, so an attached device does not receive on its own channel meanwhile (as OT). It needs an enabled IPv6 interface and no running Joiner.
- An attached, router-eligible FTD (REED child, router, leader) answers MAC Beacon Requests with a beacon, as OT (`Mle::SetStateChild` / `SetStateRouterOrLeader` set `Mac::SetBeaconEnabled`). By default the beacon has no payload, as OT without `OPENTHREAD_CONFIG_MAC_OUTGOING_BEACON_PAYLOAD_ENABLE` (Thread 1.2.1 removed beacon payloads). Difference: OT chooses the payload at compile time; here `Instance::set_beacon_payload_enabled` turns on the Thread beacon payload at run time (network name and extended PAN ID from the Active Dataset, joining permitted from the Steering Data, native commissioner from the Border Agent). `OPENTHREAD_CONFIG_MAC_BEACON_RSP_WHEN_JOINABLE_ENABLE` (beacons from a detached, non-router-capable device while joinable) is not implemented.
- **Async scans**: `OpenTrust::scan` is the MLE discovery scan (OT `otThreadDiscover`; the `Instance` result carries the network name, extended PAN ID, Steering Data and Joiner port), not `otLinkActiveScan`, and has no duration parameter (300 ms per channel). The callback gets `Option<&DiscoverResult>`, `None` at the end. Dropping the future does not cancel the scan (no cancel API in the `Instance`).

### esp-rs `openthread` compat surface (`opentrust-embassy`, feature `openthread-compat`)

- Signatures were taken from the esp-rs `openthread` sources at commit 705c557 (`lib.rs`, `scan.rs`, `dataset.rs`). `OpenThread` carries the generics of `OpenTrust` and is created from `Resources` (`new`, or `new_with_udp_srp` with placeholder `OtUdpResources` / `OtSrpResources`), `run` also takes the `Alarm`, the error type is `OtError(opentrust_core::Error)`, and `DeviceRole` has no `Other` variant.
- Defaults instead of data: `mle_counters`, `ip_counters` (all zero); `mac_counters` fields the MAC does not keep (unicast / broadcast, no-ack-requested, other, busy channel, duplicates, FCS) are 0; `NeighborInfo` age, frame counters, last RSSI and error rates; `RouteInfo` ext address, LQIs and age; `full_network_data` of a neighbor is its FTD flag.
- `NotImplemented` / no effect: `set_csl_period`, `set_child_timeout`, `set_child_supervision_*`. `scan` is the MLE discovery scan and ignores `duration_millis`. `srp_set_conf` applies only host name and addresses, `srp_add_service` ignores subtype labels, `srp_remove_service` ignores `immediate`.
- Not provided: the DNS client calls, `detach_gracefully`, `buffer_info`, `with_instance`, raw `rx` / `tx`, the pending-dataset components. The native API covers DNS (`OpenTrust::dns_*`).

## rs-matter integration (`opentrust-matter`)

Reference points: `rs-matter-embassy` (`src/ot.rs`, `src/nal.rs`, `src/wireless/thread.rs`) over the esp-rs `openthread` crate and `edge-nal-openthread`.

- **No edge-nal layer.** `rs-matter-stack` 0.4 consumes its own `NetStack` / `NetSocket` traits (the transport's `NetworkSend` / `NetworkReceive` / `NetworkMulticast`), not `edge-nal`; `rs-matter-embassy` bridges them with `NalSocket` over `edge-nal-openthread`. `MatterNetStack` implements them directly over `opentrust_embassy::UdpSocket` (one fewer layer, no `edge-nal` dependency, MSRV from rs-matter only). The three halves of a split socket are the same `SocketHalf` type sharing one socket.
- **IPv4 is refused**, not silently accepted: a bind, peer or group that is IPv4 is `ErrorCode::NoNetworkInterface` / `InvalidPeerAddr` (the esp-rs path returns an unsupported error from edge-nal).
- **Not `Send`.** The rs-matter `send-sync` feature (work-stealing executors) is not supported: the sockets use `Cell`s and the handle shares a `RefCell` behind the `RawMutex`.
- **A REED answers Address Queries** for its ML-EID now: `Instance::sync_netif` subscribes a router-eligible FTD child to the all-routers groups (OT `Mle::SetStateChild`); before, a REED's ML-EID was unreachable from the mesh until it became a router (found by the Matter port test, where the leader sends to the child's ML-EID).
- **mDNS = SRP + DNS-SD (`SrpMdns`)**, like `rs-matter-embassy`'s `OtMdns`: no mDNS socket on Thread. Differences from `OtMdns`: the host addresses are chosen by the SRP client (`srp_enable_auto_host_address`: ML-EID and off-mesh-routable addresses) instead of being copied from the `ipv6` list rs-matter passes; the host name is the hex extended address (`OtMdns` uses the MAC too); subtypes are registered (`_L`, `_S`, `_V`, `_T`, `_CM`, `_I`; the esp-rs compat surface drops them), for which `opentrust_dns::srp::MAX_SUBTYPES` went from 4 to 5 (+288 B per `Instance`); the services are removed from the server when the `run` future is dropped (drop guard; the esp-rs path relies on `srp_remove_all` of the next start); resolve requests are retried every second while rs-matter waits, a browse request is answered with one DNS-SD browse (plus a per-instance resolve when the server sends no additional records) and not repeated within the window. The DNS client's default server follows the SRP server (auto-start), so a node without an SRP server in its Network Data cannot resolve peers (OT: `otDnsClientSetDefaultConfig` falls back to the same).
- **`NetifDiag` (`ThreadNetif`)** reports one interface `thread0` (index 1) with the 8-byte extended address, the link-local address first, then the ML-EID, then global / off-mesh-routable addresses; the RLOC and ALOCs are left out (they change with the role and are not endpoints a peer should keep). `operational` is "attached". `rs-matter-embassy`'s `OtNetif` reports every unicast address in stack order.
- **`ThreadNetCtl` (Thread Network Commissioning backend).** One object implements `NetCtl`, `NetCtlStatus`, `WirelessDiag` and `ThreadDiag`; `rs-matter-embassy` splits the equivalent over `OtNetCtl` / `OtNetCtlStatus`. `scan` is the MLE discovery scan of `OpenTrust::scan` (all 2.4 GHz channels, 300 ms each; it enables the IPv6 interface first, discovery needs it) and filters on an Extended PAN ID (8 bytes) or a network name; a filter without a match is `NetworkNotFound`. `connect` stops Thread, sets the Active Dataset from the TLVs, starts Thread and waits up to 20 s (`rs-matter-embassy` uses the same) for **child or router**: a node that formed a partition of its own (leader after a failed attach, which OT's `Mle` does within seconds for a router-eligible device) is not a successful connect, because the commissioner asked for an existing network; on timeout Thread is stopped again (the esp-rs path leaves it running) and `OtherConnectionFailure` is returned. Connecting to the network the node is attached to returns at once. `set_enabled(false)` stops Thread; `true` is a no-op (`connect` starts it). Advertised: Thread version 5 (1.4), router / full Thread device bits only with the `ftd` feature, sleepy end device capable always; no border-router bit.
- **`ThreadDiag` defaults.** Role mapping as in the research notes (disabled `Unspecified`, detached `Unassigned`, child with the receiver off when idle `SleepyEndDevice`, router-eligible FTD child `REED`, other child `EndDevice`). Values are `None` while not attached (channel, PAN ID, ext PAN ID, name, mesh-local prefix, leader data, RLOC16, dataset-derived data). Where the `Instance` keeps no data the neighbor `age`, frame counters, `last_rssi`, frame / message error rates and the route table `ext_address`, link qualities, `age` are 0 / `None`; `full_network_data` follows `full_thread_device`; the route table lists the other routers only (no entry for the node itself); the MLE counters and the MAC counters the MAC does not keep (unicast / broadcast split, duplicates, FCS errors, address filtered) are 0; `overrun_count` 0; `pending_timestamp` / `delay` `None`; no network faults. `ChannelPage0Mask` is the dataset channel mask as 4 big-endian bytes of a bit-per-channel mask (bit n = channel n).
- **ICD hooks (`IcdFollower`).** rs-matter has no network-driver trait for ICD, only `Icd::net_params` / `wait_net_changed`, which a driver follows (`rs-matter-embassy` passes the intervals to `OpenThread::set_poll_period`). `IcdFollower` applies the poll interval with `Instance::set_poll_period` (effective period: the shorter of it and the stack's own) and offers `set_sleepy` for the link mode. Not applied, the `Instance` has none of it: the child timeout derived from `max_poll_interval_ms` (a slow interval longer than the stack's child timeout makes the parent age the child out), CSL, child supervision (the esp-rs compat surface has no-op stubs for them).
- **`ThreadRunner` (`ThreadDriver` / `ThreadCoexDriver`).** `rs-matter-embassy` has `EmbassyThread` (radio + `OtNetContext`, creating the `OpenThread` per run) and an `OtPersist` task the application races itself. `ThreadRunner` owns the radio and alarm (borrowed per run, so a run can be dropped and started again), the adapters of this crate and the persistence, and races `OpenTrust::run`, `ThreadPersist::run`, the ICD follower (optional `Icd`) and the task in one `select`; the task's result is returned and the pending settings are flushed once when it ends. It hands the task `&ThreadNetCtl` (the `ThreadDriver::NetCtl` type) and shares one `ThreadNetCtl` between runs, so the last status / network ID survive a restart. `ThreadCoexRunner` wraps a `ThreadRunner` and a `GattPeripheral` for `ThreadCoexDriver`; the BLE stack is not ours.
- **Settings persistence (`ThreadPersist`).** Same blob format as `OtPersist` (`[key:u16le][len:u16le][value]*` in one `KvBlobStore` blob) under the first vendor key of rs-matter (`0x1000`; `OT_SETTINGS_KEY` of `rs-matter-embassy` is its own constant), so an existing blob is readable if it uses the same OT key numbers. Persisted keys: Active / Pending Dataset, NetworkInfo, ParentInfo, ChildInfo, SLAAC IID secret, DAD info, SRP ECDSA key, SRP client info. The change trigger differs: `OtPersist` waits on a change callback of its RAM settings; here `SettingsStore::change_count` (a counter the `RamSettings` implement) is compared after every step of the node and wakes `wait_changed`, so a settings write with no other state change is seen; a store without the counter is seen only with the next state event. The write is debounced (5 s after the first change, the blob re-serialised at write time) and skipped when a 64 bit FNV hash of the serialisation equals the last one loaded or written. Frame counters: the `Instance` writes NetworkInfo when a counter reaches the stored-ahead value (1000 frames, as OT) and the persistence adds no write of its own, so sustained traffic costs about one blob write per 1000 frames. The blob is rewritten as a whole (the `KvBlobStore` has no partial update). A load replaces the persisted keys of the instance and happens once per runner before the first run, not on a restart with live resources.
- **`Instance::settings()` / `settings_mut()`** (OT has no such accessor; its settings are a platform module) give the facade and the persistence access to the store; `settings_mut` is for restoring before `thread_start`.
- **Test harness.** `opentrust_sim::testing` (feature `testing`) holds the in-memory medium and lock-step virtual-time driver of the `opentrust-embassy` tests plus a virtual `embassy-time` driver, so rs-matter's own timers run in the same virtual time as the Thread nodes (rs-matter's tests use the real-time `embassy-time/std` driver). One time driver per binary: a test binary using the harness must not enable `embassy-time/std` (rs-matter `os`).

## Message buffers

- OpenThread has one message pool (`OPENTHREAD_CONFIG_NUM_MESSAGE_BUFFERS`, default 44 buffers of 128 bytes) shared by every queue. OpenTrust uses the same buffer size and chained storage (`opentrust_core::bufpool`) but each queue (UDP receive queues, outbox, Border Agent outbox, indirect queue, forwarder held datagrams, CoAP pending requests and cached responses, DNS/SRP datagrams) owns its own pool with a const-generic size, so exhaustion in one queue does not starve another and the total is a compile-time bound. Allocation failure is `NoBufs`, as in OpenThread.
- The reassembler, the forwarder receive buffer and the MAC transmit queue still hold full-MTU buffers per slot.
- **On-off light test (`tests/light.rs`).** The light runs rs-matter-stack's `run_thread_oper` (Thread only, no BLE) over `ThreadRunner`; the Thread dataset is preset on the node (`set_active_dataset` + `thread_start` before the runner starts) instead of provisioned by the commissioner through the Network Commissioning cluster, because that path needs a BLE phase (`run_thread_no_coex` / `run_thread`) and the driver has no GATT peripheral. `ThreadNetCtl::connect` is therefore covered by its own test only, not by the Matter flow. The controller is rs-matter's `onboard::Commissioner` on the leader node over `MatterNetStack`; operational address resolution on the controller is a small stub answering with the light's ML-EID (as in rs-matter's own commissioning test), not DNS-SD through `SrpMdns`; the light's registrations at the fake SRP server are asserted. Test attestation (`allow_test_attestation`) and the test DAC / passcode of rs-matter are used. The test is not an `examples/` program: it needs the fake SRP server and the virtual time harness, which are test-only.

## nRF52840 platform (`opentrust-nrf`)

- **No MAC offload.** The `radio-embassy` backend wraps `embassy-nrf`'s `radio::ieee802154` driver and reports no `MacCapabilities` and only `ENERGY_SCAN` / `SLEEP_TO_TX`: address filtering, immediate ACK, ACK matching, ACK timeout, retries, CSMA backoff and transmit security are done by the OpenTrust MAC in software. OpenThread's nRF platform uses Nordic's 802.15.4 driver (hardware ACK, CSL, timed TX/RX). A software MAC cannot reliably meet the 192 us immediate-ACK turnaround (and the RX-after-TX ramp-up of this driver) against strict peers; the `radio-nrf802154` backend (below) uses Nordic's driver.
- **CCA.** The hardware does carrier-sense CCA only; the threshold of `transmit` is ignored (`Some` = CCA on, `None` = CCA disabled by an unreachable ED threshold). A busy channel fails the transmit with `TxFailed`, which the MAC maps to a channel access failure.
- **RSSI / timestamps.** The RSSI of a received frame is estimated from the hardware LQI byte (energy detect, 0.25 dB per LSB over -94 dBm), not sampled. `timestamp_us` is the embassy-time instant when the frame was read, not the SFD time. Energy scan samples RSSI directly from the RADIO registers every ~100 us and returns the maximum.
- **TX power** is snapped to the nearest supported value not above the request (nRF52840 table, max +8 dBm); the default reported is 0 dBm.
- **Receive cancellation.** A frame that finished while no `receive` future was alive (during a transmit or energy scan) is lost; frames failing the CRC are skipped.
- **Time base.** `EmbassyClock` / `EmbassyAlarm` inherit the `embassy-time` tick rate (32.768 kHz with the RTC1 driver, 30.5 us resolution).

### `radio-nrf802154` backend (Nordic driver + MPSL)

- **Source of the mapping.** `nrf_802154::OpenThreadRadio` of sysgrok/nrf-802154 (the mapping onto esp-rs/openthread's `Radio`), ported to OpenTrust's `Radio` trait; the esp-rs `openthread` crate is not a dependency. The driver crate is pinned to a git commit (012c01c) because the released 0.1.0 has no timed receive, CSL or secured enhanced ACKs. The Rust crates are MIT OR Apache-2.0; the driver is C (BSD-3-Clause source), and the service layer and MPSL are Nordic's prebuilt binaries under a Nordic-only licence (`opentrust-nrf` crate docs).
- **Capabilities.** All `MacCapabilities` (hardware ACK both ways, filtering, source match, promiscuous) and the PHY capabilities `ACK_TIMEOUT`, `CSMA_BACKOFF`, `AUTO_SLEEP`, `TRANSMIT_FRAME_POWER`, `RECEIVE_TIMING`, `TRANSMIT_TIMING`, `TRANSMIT_SEC`, `ENERGY_SCAN`. Not reported: `TRANSMIT_RETRIES` (the driver does not retransmit; `SoftMacNeeds` is `RETRANSMIT` only), `SLEEP_TO_TX`, `ALT_SHORT_ADDR` (the hardware filter matches one short address; `Config::alt_short_addr` is ignored). CSL accuracy 20 ppm (the 32.768 kHz crystal MPSL is set up with) and uncertainty 120 us (the wrapper's default, not measured against a peer here).
- **Energy scan** repeats the driver's RSSI measurement (`nrf_802154_rssi_measure_begin` / `nrf_802154_rssi_last_get`, receiver on) every ~150 us for the requested duration and returns the maximum. The driver's own energy detection (`nrf_802154_energy_detection`) is not used: `nrf-802154` delivers its result into private state.
- **Unsafe code.** Three direct calls into the C driver (time base, RSSI) in `radio_nrf802154.rs` carry an `allow(unsafe_code)` on that module; the rest of the workspace stays free of it.
- **Critical sections and clocks.** MPSL needs a critical-section implementation that leaves its zero-latency interrupts unmasked, so the firmware must not enable `cortex-m/critical-section-single-core` with this backend (the firmware's `radio-embassy` feature enables it, `radio-nrf802154` uses `nrf-mpsl`'s). MPSL owns the LF clock (crystal) and HF clock requests; `embassy_nrf::init` keeps its default clock configuration. `RTC0`, `TIMER0`, `TEMP`, `PPI_CH19/30/31` belong to MPSL, `EGU0`, `TIMER2`, `RTC2` to the driver; `RTC1` stays the embassy time driver and `RNG` the entropy source (neither MPSL nor the driver uses it).
- **Receive and reception timestamps** come from the driver's microsecond clock (`nrf_802154_time_get`, SFD-referenced via `PsduMeta::phr_time`), not from `embassy-time`.

- **Frames with another key ID mode than 1 on a `TRANSMIT_SEC` radio.** OpenThread's `SubMac::ProcessTransmitSecurity` leaves key ID mode 0 and 2 frames to `Mac`, which secures them in software. OpenTrust's MAC first sent every secured frame to a `TRANSMIT_SEC` radio unsecured; the nRF 802.15.4 driver, which holds only the three key ID mode 1 keys, rejected key ID mode 2 frames (MLE Announce) with `KEY_ID_INVALID`. Fixed against the OpenThread interop test: such frames are secured in the MAC (`prepare_frame`), and the key index of mode 1 frames is set to the radio's current key for every attempt (frames queued before a key sequence switch carry the old index), as OpenThread does.
- **Transmit failures by cause.** `opentrust_nrf::tx_error_stats()` counts the driver's transmit errors (busy channel, timeslot ended/denied, no ACK, no memory, aborted, invalid ACK, other) for the `radio-nrf802154` backend; the MAC still folds them into the OpenThread-style `ChannelAccessFailure`/`NoAck`. Diagnostics only, nothing in OpenThread corresponds.

### Interoperability test against OpenThread on two nRF52840 DKs

- **Setup.** OpenThread `ot-cli-ftd` (ot-nrf528xx `d2c0b13`, OpenThread `e5629fa`, UART transport) against `examples/nrf52840-leader` (`--bin node`, features `child-only` / `leader`, or the Leader binary), both with `DATASET_HEX` of the firmware (channel 25: channel 15 is busy at the test site, energy scans show -38 dBm peaks and 120 to 256 failed channel accesses per boot). Drive scripts and the OpenThread CLI driver are in `examples/nrf52840-leader/tools`.
- **Behaviour observed, same as OpenThread.** A Leader that finds another partition attaches to it as a child (after about 20 to 60 s) and upgrades to a router after a further 15 to 100 s; an OpenThread router takes over a missing leader after about 120 s.
- **Open: `radio-embassy` backend.** Against OpenThread it neither attaches as a child (still detached after 140 s, 139 frames sent, the peer sends no Parent Response and counts 8 security errors) nor is joined as a Leader. The same stack over the Nordic driver works, so the difference is in the software MAC path or the `embassy-nrf` radio layer; not diagnosed (needs a packet capture or OpenThread logging, the peer build has none). Ambient 802.15.4 frames from other networks are visible to this backend (it has no hardware address filter): hundreds of `rx_dest_addr_filtered` / `rx_err_no_frame` counts.
- **Not covered.** No packet capture (no sniffer): frames were judged by logs, ACKs and the peers' MAC counters. CSL, SED polling and security-level corner cases were not exercised against the peer.

## Flash settings (`opentrust-flash`)

- **Deferred, per-key writes.** OpenThread's reference platform (`settings.cpp` of ot-nrf528xx, flash through `nrf_fstorage` / the NVMC) writes each `otPlatSettings*` call to flash before it returns, one record per call, and deletes by marking records. `opentrust-flash` keeps the settings in a RAM image (`SettingsStore` over it is synchronous and never waits for flash) and a separate async writer (`FlashWriter::flush`) persists the keys that changed since the last flush, one entry per key holding all its values. The reason is the `radio-nrf802154` backend: with MPSL running, flash erases and writes must go through MPSL's timeslot API (`nrf_mpsl::Flash`), which is async; a synchronous store would block the executor for a page erase (about 85 ms) or collide with radio timeslots. Consequence: a power cut loses what changed after the last completed flush (the firmware flushes about 50 ms after the node's change notification, so milliseconds). Flash itself is never left corrupt.
- **Frame counters.** The MAC and MLE frame counters are in `NetworkInfo`, written by the instance when a counter reaches its stored-ahead value (1000 frames, as OpenThread). With the deferred write the persisted value reaches flash a few tens of milliseconds late; a reboot therefore never rewinds the counter unless the node sent 1000 frames inside that window. Verified on the board: three consecutive resets stored 3000, 4000 and 5010 as the MAC counter and the OpenThread peer counted no security errors.
- **Format.** Not OpenThread's (a stream of fixed-size records with a swap area and 4 byte aligned `OT_SETTINGS_...` headers, `settings_flash` of the posix platform) but a two-bank append-only log: bank header (magic, sequence number, CRC-16), then CRC-16 protected entries `key, count, values[]`; the newest entry of a key wins, `count` 0 deletes it. A full bank is compacted into the other one (erase, one entry per key, header last). The key space and the multi-value semantics (`set` replaces all values, `add` appends, `delete(index)` shifts later values down, `wipe`) are OpenThread's; a `delete` of one value of a multi-value key rewrites all its values as one entry, so no state with only some of the values is ever on flash.
- **Wipe (factory reset).** `wipe` rewrites an empty bank and erases the old one, so no old value stays in flash; `delete` of a key leaves its older entries in the log until the next compaction. OpenThread's `otPlatSettingsWipe` erases the flash pages.
- **Bounded RAM.** The image has a fixed byte capacity and tracks a fixed number of dirty keys (more dirty keys than the list holds make the next flush a full compaction). The set of keys is open (any `u16`), the number of distinct keys in the image is not limited except by the capacity.
- **Regions of the nRF52840 firmware** (`examples/nrf52840-leader/memory.x`): the last 24 KiB of flash are outside the `FLASH` region the linker uses (`LENGTH = 1000K`, `__nvm_start` symbol): Thread settings 0xFA000..0xFC000 (two banks of one 4 KiB page), Matter key-value store 0xFC000..0x100000 (two banks of two pages). `probe-rs run` / `download` erase only the sectors of the image, so the settings survive a reflash; `--chip-erase`, `probe-rs erase` and `nrfjprog --eraseall` remove them.
- **Factory reset** is Button 1 held at boot: the firmware erases the whole 24 KiB area before mounting. OpenThread's nRF platform has no button; `otInstanceFactoryReset` is an API call (the `Instance` has `factory_reset` too, which wipes through `SettingsStore::wipe`).
- **Matter light.** The Thread settings stay a `ThreadPersist` blob inside the rs-matter key-value store (one flash region for everything rs-matter and Thread persist, so one writer task); `FlashKv` is the `KvBlobStore` over the same RAM image. The Thread-settings region is unused by the light firmware.

## RAM and stack (`opentrust-instance`, `opentrust-embassy`)

- OpenThread's `otInstance` lives in static storage (`otInstanceInitSingle`) or in a caller-provided buffer (`otInstanceInit`), so it is never moved. In Rust a value of that size (about 100 kB with default features) would be built on the stack and moved by value. OpenTrust therefore has in-place constructors, `Instance::init(&mut MaybeUninit<Instance>, ...)` and `Resources::init(&mut MaybeUninit<Resources>, clock, |slot| Instance::init(slot, ...))`; each component is built by a small non-inlined helper straight into its field, so the stack peak of the construction is the largest component (about 11 kB), not the instance. `Instance::new` / `Resources::new` remain for hosts and tests and are implemented on top of the in-place paths.
- `Resources` guards its state with its own `RawMutex` plus a borrow flag instead of embassy's `Mutex<RefCell<_>>`, because the latter cannot be initialised in place. Re-entrant access panics as before.
- The `Instance::poll` service steps (`service_mac`, `service_timers`, ...) are `#[inline(never)]` so the locals (MTU-sized datagram buffers) of the steps do not add up in one frame; this trades a few call instructions for stack depth. OpenThread has no equivalent concern because its messages live in the heap pool.

## On-network Matter light (`examples/nrf52840-light`)

- **Build-time dataset.** `OPENTRUST_DATASET` (hex of `ot-ctl dataset active -x`) is embedded by `build.rs`; OpenThread platforms take the dataset at run time (CLI, `otDatasetSetActive`, commissioning). The embedded dataset is only used while the flash holds no Active Dataset: a stored network always wins, as a stored dataset does in OpenThread; Button 1 at boot (factory reset) erases it. With a dataset the node calls `thread_start` (restore or attach, forming a partition only when no router answers, like `otThreadSetEnabled`); without one it forms a network at once (`become_leader`), as before. A cargo feature `med` builds a minimal end device (`Config::end_device`, never router eligible); the default is router eligible, as OpenThread's FTD.
- **SRP host addresses** follow `otSrpClientEnableAutoHostAddress`: the preferred, non-link-local, non-mesh-local addresses (SLAAC addresses of the border router's on-mesh prefixes), the ML-EID only when there are none. Covered by a simulator test with a border-router-like node.
- **Debugger and flash erase.** On the nRF52840 with `radio-nrf802154`, flash erases go through MPSL's timeslot API; halting the core while one runs (`probe-rs attach` after `probe-rs reset`) makes MPSL assert (`MultiprotocolServiceLayer: 106:179`). `probe-rs run` and a standalone boot erase fine. Affects the first-boot format of the key-value store, factory reset and compaction only when a debugger interferes; OpenThread's nRF platform uses the same timeslot flash driver and has the same constraint.
- **Heap.** The only heap user of rs-matter's RustCrypto backend is the PKCS#10 request built at commissioning (`x509-cert`): 531 bytes at peak on the host (`crates/opentrust-matter/tests/heap.rs`), so the firmware heap stays 4096 bytes. rs-matter's bump area is allocated once at start (26760 bytes of 28 kB); PASE and CASE run on the stack and in fixed buffers.
- **SRP host name conflicts.** OpenThread's SRP client reports `kErrorDuplicated` and leaves the choice of a new host name to the application. `SrpMdns` does it: after a YXDOMAIN answer it registers the host as `<EUI-64>-1`, `-2`, ... (the server keeps a host name for its key for the key lease of days, so a node that lost its SRP key by a factory reset could otherwise never register again). `Instance::srp_take_failure` exposes the last failed update; `SrpClient::host_name` the current name (like `otSrpClientGetHostInfo`).
- **Restarted mDNS future.** When the netif restarts `SrpMdns::run` (for instance the mesh-local prefix changes after attaching with a partial dataset) the SRP client still holds the removal of the old service; adding the same service again returns `Already` as in OpenThread. `SrpMdns` retries every second until the removal is done and keeps the host name set by an earlier run.
- **Partial dataset.** A dataset with only channel, PAN ID, extended PAN ID, network name and network key attaches and learns the mesh-local prefix, timestamp, PSKc, channel mask and security policy from the parent (simulator test `attaches_with_a_partial_dataset_and_learns_the_rest`, and on the board against an ot-br-posix border router).
- **Attach before forming.** With a dataset the FTD light needed up to 8 s on the board before it formed a partition of its own (Leader) and about 3 s more to merge into the border router's partition; OpenThread does the same after its parent search rounds.

## BLE commissioning (`opentrust_matter::ble`, `examples/nrf52840-light` feature `ble`)

OpenThread has no BLE; its Matter story is `rs-matter-embassy` over the esp-rs `openthread` crate. What differs from that reference:

- **The BTP GATT peripheral is a port, not a dependency.** `opentrust_matter::ble` (feature `ble-trouble`) is `rs-matter-embassy`'s `ble.rs` + `ble/trouble.rs` (revision 252cc60, MIT OR Apache-2.0) adapted to the logging shim of this crate; `rs-matter-embassy` itself is not used, since it brings the esp-rs `openthread` crate, `embassy-net` and its own `MatterStack` assembly. The BLE host is `trouble-host` 0.8 (peripheral and gatt only, no central, no security manager: Matter secures the link with PASE), the controller the Nordic SoftDevice Controller through `nrf-sdc` 0.4 (`peripheral` library variant), which shares the `nrf-mpsl` 0.4 instance (`init_mpsl`) with `nrf-802154`; one copy of `nrf-mpsl` / `nrf-mpsl-sys` in the lock file.
- **The controller exists only while BLE advertises.** `SdcGatt` (light example) builds the SoftDevice Controller inside `GattPeripheral::run` and drops it (`sdc_disable`) when rs-matter closes the commissioning window, as `rs-matter-embassy`'s `SdcGattPeripheral`; between commissioning windows MPSL serves Thread alone. The peripheral and the controller run concurrently with Thread (`ThreadCoexRunner` / `run_thread`), so a commissioner on BLE can hand over the dataset while Thread scans and attaches.
- **Two RNG versions.** `nrf-sdc` 0.4 takes a `rand_core` 0.9 `CryptoRng`, rs-matter and embassy-nrf use 0.10; the light bridges them with a 15 line adapter (`rs-matter-embassy` uses `rand::RngAdaptor`).
- **Unprovisioned light.** With the `ble` feature a light with no stored Active Dataset and no `OPENTRUST_DATASET` leaves Thread disabled and waits for `AddOrUpdateThreadNetwork` / `ConnectNetwork` over BLE (`ThreadNetCtl::connect`); it no longer forms a network of its own. `--no-default-features` builds the Thread-only light as before; a build-time dataset still attaches at once (and BLE is also offered while the light has no fabric).
